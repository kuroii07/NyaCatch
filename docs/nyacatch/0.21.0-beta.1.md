# 0.21.0-beta.1 · NVIDIA 硬件压制

视频压制页增加编码设备选择：CPU软件编码或NVIDIA NVENC，支持H.264/H.265和MP4/MKV。默认CPU，旧草稿和旧任务保持原行为。NVIDIA选项由捆绑FFmpeg实际初始化并编码测试帧后开放；每种编码分别检测，支持重新检测。没有可用显卡、驱动或检测超时时不允许提交GPU任务，也不会悄悄换成CPU。

CPU继续使用CRF。NVIDIA使用独立CQ（1～51，越小通常画质越高、文件越大），两者数值不等价。NVENC的快速/均衡/较慢分别使用P2/P4/P6，VBR恒定质量、HQ调优。保留原尺寸/仅缩小、帧率、字幕烧录、音轨复制或AAC和短片试压；缩放、解码与字幕仍由CPU处理，不保证每个文件都更快或更小。

目标体积模式继续使用CPU两遍编码，选择NVIDIA后目标体积按钮不可选；需要先明确切回CPU，服务端也拒绝GPU目标体积组合。编码设备和CQ随原任务选项保存，重启、重试沿用；运行时GPU失败会标记任务失败，可查看错误后切回CPU重新创建。

预览上方有“添加字幕/更换字幕”按钮，使用原SRT/ASS选择和验证流程；右侧字幕设置放在编码设备下方，默认收起，从快捷按钮添加时展开。记录抽屉显示编码设备及CQ或CRF。窄窗口下保留更大的预览区，左侧内容可内部滚动；主动停止编码沿用取消提示，硬件失败另行提示。

修正试压并复制音轨时的输入seek预滚包：输出前丢弃负时间音频包，避免MKV把视频起点后移。源文件、整片音轨复制和原有任务表不改变。

首轮硬件验收机器：RTX 4080 SUPER，H.264/H.265。只覆盖8位SDR；AMD/Intel/AV1、GPU解码/滤镜、HDR/10位与跨机器显卡组合尚未纳入。本机目录包验证和交付证据在父项目`outputs/reports/0.21.0/`，正式GitHub自动更新仍属后续范围。
